A) PARTE A - Roles y permisos

1. Conectarse a food_store_tp4. psql solicita la contraseña de forma interactiva:
psql -U postgres -d food_store_tp4 -W

2. Ejecutar el script de roles:

3. Asignar contraseñas sin guardarlas en archivos:

\password admin_datos

4. Ver roles creados:
\du

5. Ver permisos por tabla:
SELECT grantee, table_schema, table_name, privilege_type
FROM information_schema.role_table_grants
WHERE grantee IN ('rol_app_lectura','rol_app_escritura','rol_soporte','rol_reportes','app_web','admin_datos')
ORDER BY grantee, table_name, privilege_type;

6. Ver permisos por columna:
SELECT grantee, table_schema, table_name, column_name, privilege_type
FROM information_schema.role_column_grants
WHERE grantee IN ('rol_app_lectura','rol_app_escritura','rol_soporte','rol_reportes','app_web','admin_datos')
ORDER BY grantee, table_name, column_name, privilege_type;

B) PARTE B - Auditoría

1. Activar parámetros del servidor:
ALTER SYSTEM SET log_connections = on;
ALTER SYSTEM SET log_disconnections = on;
ALTER SYSTEM SET log_statement = 'all';
ALTER SYSTEM SET log_line_prefix = '%m [%p] %u@%d %h ';
SELECT pg_reload_conf();

2. Verificar configuración:
SHOW log_connections;
SHOW log_disconnections;
SHOW log_statement;
SHOW log_line_prefix;

Se usa 'all' temporalmente para que también quede registrada la lectura SELECT. Al
terminar la captura, volver al nivel mínimo requerido por la consigna:
ALTER SYSTEM SET log_statement = 'mod';
SELECT pg_reload_conf();

3. Ejecutar prueba de lectura/escritura y revertir los cambios de datos:
BEGIN;
SELECT id, nombre, email FROM public.usuario LIMIT 5;
INSERT INTO public.categoria (nombre, activo)
VALUES ('Auditoria TP Unidad 5 20261006', true)
ON CONFLICT (nombre) DO NOTHING;
UPDATE public.producto
SET precio_lista = precio_lista + 5
WHERE id = (SELECT MIN(id) FROM public.producto);
ROLLBACK;

4. Intento de login fallido:
psql -U usuario_invalido -d food_store_tp4 -h localhost -W

5. Consultar log:
SHOW log_directory;
SHOW log_filename;

Windows/PowerShell: revisar el archivo de log del servidor PostgreSQL desde la ruta devuelta arriba.
Linux/macOS: tail -n 100 /ruta/del/log/postgresql.log

C) PARTE C - Simulacro de incidente

1. Reconstruir la autenticación aislada para el laboratorio como postgres:

La función usa exclusivamente demo@foodstore.test y una contraseña ficticia; no modifica

2. Confirmar la firma:

3. Probar dos fallos y un acceso exitoso usando solo la cuenta sintética:

4. Lectura masiva en el entorno propio:

5. En otra consola, iniciar sesión como app_web e intentar escalar privilegios:
psql -U app_web -d food_store_tp4 -h localhost -W
GRANT admin_datos TO app_web;

Se espera un error de privilegios insuficientes. Ejecutar el GRANT como postgres no
prueba el límite de permisos de app_web. Si el intento inesperadamente tiene éxito,
conectarse como postgres y revocar la membresía:
REVOKE admin_datos FROM app_web;

6. Desde la sesión postgres, verificar las membresías:
SELECT r.rolname AS role_name,
       m.rolname AS member_name
FROM pg_auth_members am
JOIN pg_roles r ON r.oid = am.roleid
JOIN pg_roles m ON m.oid = am.member
WHERE r.rolname = 'admin_datos';

7. Repetir la secuencia con logging completo y extraer el fragmento del incidente.
